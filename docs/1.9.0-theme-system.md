# ModernFormsNext 1.9.0 theme system

> [!NOTE]
> This document records the theme-system scope included in ModernFormsNext 1.9.0. Android support
> remains experimental; see the platform section before relying on it in an application.

## Added

- application-lifetime `ThemeManager` with synchronous/asynchronous thread-safe apply requests;
- mutable `ThemeDefinition`, typed/custom tokens, and immutable resolved snapshots;
- single-base inheritance with missing-base, cycle, depth, key/value, and type diagnostics;
- dedicated theme-resource fallback below `Application.Resources`;
- atomic UI-thread commit, rollback, documented events, counters, and safe diagnostics;
- version 1 strict JSON string/stream/file load/save with Brush converters and security limits;
- animated color, custom numeric, solid, and compatible gradient transitions through the shared
  animation scheduler when explicitly enabled; theme application is immediate by default;
- Windows light/dark and reduced-motion preference provider;
- built-in ModernFormsNext Light/Dark definitions with semantic colors and Brush examples;
- ThemeManager ControlGallery page and deterministic headless coverage.

## Compatibility and migration

- static `Theme` APIs remain and are projected from the active resolved theme;
- `Theme.SetBuiltInTheme` now performs an immediate ThemeManager apply;
- existing application/window/control resources remain higher precedence than theme defaults;
- existing `ControlStyle`, CLR property setters, rendering invalidation, and Brush notifications are
  retained;
- new reusable controls should prefer typed `ThemeTokens` and dynamic resource references;
- `ThemeChanged` means commit. Observe `ThemeTransitionCompleted` or the handle completion task for
  animation termination;
- theme JSON is intentionally strict and may reject unknown fields accepted by custom legacy loaders.

## Platform status

Windows is the primary runtime target. System preference is read on apply; live OS-theme change
notifications remain future work. The Designer uses deterministic immediate fallback behavior and
starts no runtime services.

Android remains experimental. Shared theme/model/JSON/resource/scheduler code builds for Android,
and the existing lifecycle service prevents background time jumps. Android currently has no
platform theme provider, so System uses the explicit Light/Dark fallback. Emulator/device startup,
storage integration, and visual transition validation remain required before release.

## Known limitations

- no hot reload/file watcher;
- no automatic system-theme reapply;
- layout tokens, GlassBrush, NoBrush, and incompatible gradients switch immediately;
- no complete shared shadow model;
- typography line height and letter spacing are not globally consumed;
- no claim of Android runtime parity without device/emulator validation.

## Documentation and manual validation

See [Themes](themes.md), [theme JSON schema](theme-json-schema.md), and the
[ThemeManager ADR](architecture/decisions/ADR-Theme-System.md). ControlGallery contains the
interactive checklist for immediate/animated switches, replacement/cancel, motion policies, JSON,
inheritance errors, diagnostics, resize, and minimize/restore.
