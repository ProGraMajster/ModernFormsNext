# ModernFormsNext 1.11.0 release notes

ModernFormsNext 1.11.0 expands the code-first .NET 10 framework with commands,
application lifecycle and text composition, safe Designer metadata, accessibility,
testing/automation and performance diagnostics. It also fixes Windows scaling and
partial-redraw regressions. Windows remains the primary runtime; Android remains
an **experimental single-surface host**.

The release uses the existing coordinated NuGet, template, VSIX and versioned
documentation workflow. The [complete changelog](../CHANGELOG.md) covers every
merged change since the actual `v1.10.0` tag. The
[release readiness report](development/1.11.0-release-readiness.md) records source
commits, validation evidence and the limits of each claim.

## Framework, commands, lifecycle and text input

- Reusable command sources, scoped key gestures and input bindings, hierarchical
  routed command bindings, asynchronous commands and action-control integration.
- Shared application lifecycle/activation, shutdown policies and state handoff,
  Windows multi-window integration, and Android Activity recreation/Intent hooks.
- Canonical text composition with Windows IMM32 and Android InputConnection adapters
  for TextBox, multiline TextBox, RichTextBox and MarkdownEditor, including Unicode,
  selection and commit/cancel behavior across focus and popup changes.
- Android hardware shortcuts use shared command routing, with documented platform
  and editor limitations.

These features extend the existing framework contracts. Future native-view/media
hosting, a complete Android WindowKit host and process-death restoration are not
included in this release.

## Designer and Visual Studio

- Transactions, grouped undo/redo and rollback; copy/cut/paste/duplicate; revision-aware
  autosave, crash recovery and external-change conflict handling.
- Typed native host handles, View Designer/Shift+F7 routing, companion-file nesting,
  independent per-document hosts and selectable integrated or standalone windows.
- Safe source and binary custom-control discovery, inherited properties/defaults/events,
  explicit Toolbox refresh, stale/missing diagnostics and persistent placeholders.
- Designer/runtime layout parity checks use production layout.

Discovery does not execute application startup, constructors, getters, delegates or
arbitrary converters. Integrated Ctrl+S remains tracked in
[#99](https://github.com/ProGraMajster/ModernFormsNext/issues/99); use the Designer
toolbar Save button or the document close Save prompt.

## Accessibility, tests and automation

- One shared accessibility semantic model with Windows UI Automation and Android
  virtual-node adapters, including bounded composite, viewport, grid and text support.
- Optional native contrast/text-scale detection and explicit preference consumption.
- `ModernFormsNext.Testing` supplies a deterministic headless TestHost with production
  input, controlled time, scoped services and rendering snapshots.
- `ModernFormsNext.Automation` exposes semantic snapshots/actions; the optional
  `ModernFormsNext.Automation.Windows` bridge is disabled by default and uses bounded,
  authenticated local IPC over the same semantics.

These are new packages in the coordinated release. Further automation phases and
general accessibility compliance or screen-reader parity are not claimed.

## Rendering, High DPI and diagnostics

- PerformanceProfiler supplies opt-in frame/layout/allocation observations, bounded
  history, snapshots/JSON export and a diagnostics HUD.
- Windows display changes preserve logical layout and input coordinates. Local
  damage remains bounded through composition, Skia rendering and GDI presentation.
- Partial repaint/removal fixes eliminate the tested stale-pixel/ghosting regressions.
- ScrollableControl layout and wheel routing are corrected.
- Published 1.10.0 raw-pointer event numbers remain stable; `CaptureLost` uses a new
  appended value rather than shifting existing events.

The release audit exercised FHD 100% and a Windows 5120x2880 virtual display at 225%,
including transitions, resize/maximize, popups, overlays, scrolling and animation.
Its 426 pixel-oracle records have zero differences. Full-5K hover damages 46,004
pixels (0.312% of the window) with no layout pass. These are local software/native
window observations, not GPU or physical-panel scanout guarantees.

## Android validation and limitations

The final functional-source matrix passed on an Android 14/API 34 x86_64 emulator
and an Android 16/API 36 arm64 nubia NX769J physical device. Debug and Release native
functional checks passed 95/95 on the emulator and 105/105 on the phone; native
accessibility passed 64/64 in all four lanes. Release system reduced motion passed
6/6 on both targets. Temporary settings were restored.

Release APK runtime and AAB construction use profiled Mono AOT and partial SDK
trimming. Full trimming, NativeAOT and store submission are not declared. The phone
advertises 90/120 Hz but all observed test modes remained near 60 Hz; actual 90/120 Hz,
broad vendor/CJK IME, human TalkBack/gesture assessment and overnight/thermal stress
remain unexecuted. See the [Android matrix](android-release-validation.md).

## Compatibility and upgrading

Update application package references and the matching VSIX to 1.11.0, then rebuild.
The existing version policy advances library assembly versions to `1.11.0.0`.
There are no intentional package-ID, namespace, target-framework or public-member
removals, and no required `.mfdesign` schema migration.

The comparison against actual 1.10.0 packages covers eight assembly/TFM pairs.
Reviewed ApiCompat and effective Roslyn signature/nullability checks pass; the
readiness report explains the four compiler-metadata exclusions rather than calling
this an unfiltered raw-attribute pass. The enum regression found by that audit was
fixed before release preparation.

The repository and CI use patched .NET SDK and SourceLink 10.0.401 for
CVE-2026-62900 while retaining .NET 10 target frameworks. Offline API navigation now
exposes the generated namespace/type table of contents.

## Validation and release artifacts

The functional-source audit passed warning-free Debug/Release builds and
**3587 tests in each configuration**, dependency audit, package validation, an
isolated package consumer, a fresh generated application, VSIX validation, native
Designer/Windows checks and the Android matrix. The user separately confirmed the
Visual Studio Designer's visible editing, dirty marker, toolbar Save/reopen and
input/rendering across both monitors. The full fourteen-step VS checklist is not
claimed as freshly executed. Versioned-candidate results are retained in the dedicated
release PR before publication; the tag workflow rebuilds and validates the exact
tagged merge commit. The readiness report separates these evidence stages.

The coordinated release contains eleven NuGet packages, ten symbol packages, the
matching `ModernFormsNextDesigner.vsix`, and four tag/SHA-bound archives:

- `ModernFormsNext-1.11.0-docs.zip` — documentation sources, XML docs and API snapshot;
- `ModernFormsNext-1.11.0-docs-html.zip` — offline HTML documentation and API reference;
- `ModernFormsNext-1.11.0-samples.zip` — selected samples and the template reference;
- `ModernFormsNext-1.11.0-sdk.zip` — aggregate reference bundle.

Review [known limitations](known-limitations.md) before adopting platform-specific,
Designer, accessibility or trimming behavior. #62, #63 and #69 remain open for their
documented broader/future acceptance criteria; completed release checkpoints were
merged independently. Future features were not added to this release.
