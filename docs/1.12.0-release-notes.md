# ModernFormsNext 1.12.0 release notes

ModernFormsNext 1.12.0 expands code-first controls, navigation, the Visual
Studio Designer and experimental Android hosting. Windows remains the
primary runtime.

Start with the [control catalog](controls/README.md) for practical examples,
the [changelog](../CHANGELOG.md) for notable changes, and the
[upgrade guide](migrations/1.11.1-to-1.12.0.md) for migration checks.
Version 1.12.0 was released on 2026-11-22 and uses .NET 10.
[GitHub Release](https://github.com/ProGraMajster/ModernFormsNext/releases/tag/v1.12.0)

## Controls and navigation

- CollectionView, CarouselView, RefreshView, SearchBar, TimePicker and
  BindingNavigator are available. Shared recycling supports large lists;
  existing ListView consumers opt into virtualization.
- Pages, navigation stacks, tabbed and flyout navigation, AppShell routes
  and configurable headers share the framework's control and lifecycle
  contracts.
- Styling changes cover dynamic resources, brush transitions, layout-aware
  visual states, shadows, typography, ToolTip behavior and right-to-left layout.

## Visual Studio and Windows

- The Designer adds multi-selection, grouping, clipboard operations, guides,
  snapping, project assets, event-handler navigation, inherited forms and
  inherited controls. The standard VSIX uses design data and control metadata,
  with editable placeholders for unavailable project controls.
- Integrated and Separate window modes use the same document, undo, save and
  recovery semantics. Startup logging records process identity, readiness,
  host attachment and shutdown.
- Custom-chrome maximize uses the monitor's work area. The Windows validation
  covers persistent and automatically hidden taskbars at 100% and 225% DPI.
  Scrolling, window constraints, title-bar icons and notification cleanup also
  receive reliability fixes.
- Executable preview of project controls, its Windows isolation qualification
  and older .NET targeting are tracked for 2.0.0. See the
  [Designer compatibility matrix](visual-studio-designer-host.md#visual-studio-and-net-compatibility).
- Windows regression coverage checks [ToolTip composition](tooltips.md#presentation-and-lifetime)
  and vector geometry pixels after a desktop presentation following repaint. See
  [#540](https://github.com/ProGraMajster/ModernFormsNext/issues/540) for the measurement history.

## Package and documentation artifacts

The framework, backend packages, templates and standard VSIX are coordinated
at 1.12.0. The library assembly version is 1.12.0.0 for this minor line.
The first experimental Android backend package carries a deterministic
`net10.0` asset and a native Android asset. The optional Windows App SDK and WinRT
notification backends also have new NuGet package identities. Windows project and item
templates continue to generate code-first applications and `.mfdesign` files.

The versioned offline HTML includes every control guide and a searchable
DocFX reference generated from the release assemblies and XML documentation.
The release documentation also describes
[archive contents and provenance](releasing/versioned-documentation-artifacts.md).

## Android and text input

Android support remains **Experimental**. .NET 10 Android package assets and
the NativeViewHost foundation extend lifecycle, appearance and input support.

The [Android validation matrix](android-release-validation.md#1120-qualification)
records physical NX769J API 36 evidence alongside the API 23, 34 and 36
emulator evidence. The physical device sustained the tested background and
recreation profile and ran the fixture at an observed 60 Hz. Real 90/120 Hz,
physical multi-touch, broader devices and extended stress are tracked in
[#538](https://github.com/ProGraMajster/ModernFormsNext/issues/538).

The APK from official Prepare passed 107 assertions on NX769J (API 36) and 97
on the API 34 emulator. On M2003J15SC (API 31), the standard matrix failed
at `background-no-surface` after injected Home. The separate `LifecycleStress`
scenario on the same APK passed 147 assertions with a 90-second background
dwell and 36 Activity recreations after `MoveTaskToBack`.
[Official Android evidence](https://github.com/ProGraMajster/ModernFormsNext/issues/82#issuecomment-7082603546)

The [text input guide](text-input.md#1120-qualification) describes Windows IMM32
coordinate tests, real Windows HWND integration, Android InputConnection tests
and a Gboard Latin input/focus observation. Live CJK candidates, other IMEs and
layouts, human TalkBack and Android physical keyboards remain follow-ups in
[#537](https://github.com/ProGraMajster/ModernFormsNext/issues/537),
[#59](https://github.com/ProGraMajster/ModernFormsNext/issues/59) and
[#109](https://github.com/ProGraMajster/ModernFormsNext/issues/109).

See the [changelog](../CHANGELOG.md) for more details.
