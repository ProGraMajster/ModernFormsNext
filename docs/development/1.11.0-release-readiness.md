## Build tooling blocker

[CVE-2026-62900 / GHSA-23fw-v26w-5fgq](https://github.com/advisories/GHSA-23fw-v26w-5fgq)
lists Microsoft.Build.Tasks.Git 10.0.301 as affected and states that the 10.0.2xx
SDK feature band is no longer serviced. Both the explicit build dependency and
the SDK pin must use patched tooling. The already installed SDK 10.0.401 and
[SourceLink 10.0.401](https://www.nuget.org/packages/Microsoft.SourceLink.GitHub/10.0.401)
keep the .NET 10 target while aligning local and CI builds. This is a release
blocker fix, not a runtime API or framework version change. Acceptance requires
fresh restore/audit, builds, tests and packaging with no warning suppression.

## Findings and fixes during the audit

### Published pointer-event compatibility

The first raw ApiCompat run against the downloaded 1.10.0 release packages found
20 changed `RawPointerEventType` constants. Inserting `CaptureLost` after
`LeaveWindow` had shifted every subsequent value, which could misinterpret input
from an already compiled backend. The fix preserves the original 0–20 values
explicitly and assigns the additional event 21. No public member is removed.
The regression test failed 21/22 cases before the fix and passed 22/22 afterward.
This restores compatibility rather than requiring a breaking-change decision.

Raw attribute comparison also reports compiler-generated accessor/state-machine
metadata and nullable-context encoding changes. Their completed review is recorded
below; the result is not presented as an unfiltered ApiCompat pass.

### GitHub metadata reconciliation

The actual project Target 1.11.0 field, current closed states and merged PR history
confirmed #33, #42, #71, #83 and #98. Their milestone and target labels now agree;
#120's stale target 1.10 label is replaced by 1.11. The milestone description now
describes the actual frozen scope instead of future pages/navigation/AppShell.
#41/#68 remain closed, and #62/#63/#69 remain open/partial. No Future/1.12 target
was moved. The milestone contains eight closed and three open issues.

### Compatibility review against the released packages

The baseline consists of the downloaded GitHub `v1.10.0` packages, with hashes
recorded locally. An isolated baseline consumer resolves their exact compile
references. Both sides also resolve framework references; missing-type errors are
not disabled. The eight comparisons cover the seven previously published library
assemblies, including both core TFMs. Newly added libraries have no 1.10 baseline.

The first raw comparison reports 20 changed enum constants, 64 CP0014 and 12 CP0015
attribute differences. The enum values are now restored. Only these four compiler
metadata attributes are excluded from the reviewed ApiCompat run:

- `CompilerGeneratedAttribute`: automatic accessors became explicit accessors for
  notification/invalidation behavior; public accessor signatures remain covered.
- `NullableAttribute` and `NullableContextAttribute`: effective annotations are
  compared separately instead of treating equivalent compiler encoding as a break.
- `AsyncStateMachineAttribute`: PE inspection confirms the changed Markdown and
  ThemeManager generated state-machine names identify private nested types.

No ApiCompat diagnostic code or other attribute is suppressed. Public/protected
signatures, parameter names, flow-analysis and trimming attributes remain checked.
The reviewed ApiCompat invocation exits successfully for both configurations.
A separate Roslyn comparison checks **19,548 existing declarations per
configuration**, with no missing members, unresolved types or effective-nullability
changes. Its four self-test cases pass. Nine class-declaration differences are
reviewed additive interfaces on Button, MenuItem, NotifyIconMenuItem,
SkiaControlSurface (each core TFM), and DesignerSession; existing bases, interfaces,
annotations and constraints are preserved. Private async metadata and accessor
source diffs are retained with the raw diagnostics. No breaking-change owner
decision is required.

### Windows, both monitors and the Designer

The Windows display topology is FHD 1920x1080 at 100% and the additional Windows
virtual display at 5120x2880 / 225%. The test uses real HWNDs and reports actual
96/216 DPI; it does not infer physical-panel scanout from the virtual display.
The six gallery lanes include normal/maximized FHD, normal/maximized 5K, full 5K,
and return to FHD. Repeated transitions, resize, Dock/Anchor, hover/press, popups,
overlays, DataGridView scrolling, animation, moved/resized/removed controls and
partial redraw use the existing checked-in regression harness.

All 426 records have zero differences against both the complete repaint oracle
and the visible-window/back-buffer oracle. Representative 225% gallery and native
Designer images were visually inspected. The existing #58 profiler reports the
following bounded full-5K hover observation: **46,004 / 14,745,600 pixels (0.312%)**,
mean measured frame callback 1.064 ms, maximum 1.343 ms, mean GDI blit 0.040 ms,
zero layout passes. These are local software measurements, not GPU/presentation
latency guarantees. Backing generations change at display/size transitions and
remain stable during each hover lane.

The installed VSIX required Visual Studio's `/UpdateConfiguration` for the fresh
isolated profile before its command registration appeared. After that, the
ModernFormsNext command opened `MainForm.cs [Design]` and the owned host reported
normal readiness/dirty polling. This setup step is not a framework regression.
The user then reported **“Wszystko działa”** in response to the exact interactive
smoke listed in the matrix. Native-window interaction was unavailable through the
agent's UI tool, so that final observation is user supplied. Neither host logs nor
the separate native fixture are substituted for it. The complete fourteen-step
[VS checklist](../visual-studio-designer-host.md#interactive-visual-studio-validation-checklist)
is **not** claimed as freshly executed. Integrated Ctrl+S remains the documented
[#99](https://github.com/ProGraMajster/ModernFormsNext/issues/99) limitation; this
smoke used the canonical toolbar Save path.

or local user paths. The pre-existing untracked local configuration is preserved.

## Release decision

The two concrete audit blockers (unpatched build tooling and shifted published
pointer-event constants) are fixed and validated. The implemented roadmap scope
is complete; #62/#63/#69 remain open for their explicitly bounded broader/future
criteria. Their open state alone does not block merging or preparing the scoped
experimental-Android release. No Future feature is added or retargeted.

**Functional scope is ready for 1.11.0 version preparation.** The documentation
follow-up and its exact-head CI/merge are the remaining steps of this audit PR.
After those pass, use the existing release policy to create and validate the
coordinated version commit, packages, templates, VSIX and versioned documentation.
This report does not yet authorize tagging an unvalidated version commit or claim
GitHub/NuGet/Marketplace publication. Existing Marketplace approval remains a
separate publication boundary.
