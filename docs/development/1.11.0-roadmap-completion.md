## Issue #62 — text input and composition

### Initial audit, before implementation

[Issue #62](https://github.com/ProGraMajster/ModernFormsNext/issues/62) is OPEN with
target/milestone 1.11.0; its project status still said Planned at this audit.
[PR #117](https://github.com/ProGraMajster/ModernFormsNext/pull/117) already merged
the implementation at `61c15190fef81e0f986c63956220fe5658ca0dca`. The
[earlier acceptance report](codex-autonomous-issue-run.md#issue-62--acceptance-and-validated-implementation)
contains the complete original requirement mapping and source-specific evidence.
The current audit checked those requirements against current source, test inventory,
[text-input contracts and boundaries](../text-input.md), and known limitations
AND-04/TXT-03. Historical emulator results are not relabeled as current binaries.

### Validation and completion

On 2026-09-20 the production tree at `71611a16d09b6a61117d424bfe81301056efeb2d`
passed a fresh serial restore, full Debug/Release builds and **3553/3553 tests in each
configuration**, with zero failed/skipped tests in each of nine TRX files. Builds

The updated documentation passed DocFX with zero warnings/errors and validation of
all four offline archives. These local audit artifacts retain version 1.10.0; they
are not 1.11.0 release candidates.

Ctrl+Alt shortcut remained usable, and the dead-key sequence produced one `ą`.
It restored its thread-local keyboard state. This is **AUTOMATED native Windows
HKL/owned-HWND evidence with synthetic thread-local key state**, not physical typing
or manual CJK candidate-window observation. Binary informational versions matched
the production source above. Local logs and parsed TRX summaries are retained under
`artifacts/release-1.11.0/issue-62`; native evidence is
