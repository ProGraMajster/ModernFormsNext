# Getting Started with ModernFormsNext

ModernFormsNext is a code-first desktop UI framework. It uses custom ModernFormsNext controls and SkiaSharp-based rendering; it is not a XAML framework and does not use native WinForms controls for framework UI.

## Quick Start

The easiest way to get started as a contributor is by cloning the repository, restoring the solution, and running one of the sample applications.

```powershell
git clone https://github.com/ProGraMajster/ModernFormsNext.git
cd ModernFormsNext
dotnet restore .\ModernFormsNext.slnx
dotnet build .\ModernFormsNext.slnx --configuration Debug --no-restore /p:EnableWindowsTargeting=true
```

## Requirements

- .NET SDK `10.0.201`, configured by `global.json`.
- SDK roll-forward is enabled for the latest installed .NET 10 feature band.
- Windows is currently the primary and best-supported runtime target.

The main framework project targets both `net10.0` and `net10.0-windows`. Generated application templates target `net10.0-windows`.

## Run the Sample Applications

`ControlGallery` is the main manual visual test app for controls, rendering, layout, focus, input, and theme behavior.

```powershell
dotnet run --project .\samples\ControlGallery\ControlGallery.csproj
```

`ModernFormsNext.DemoApp` is different from the other samples. It represents the default application generated by the Visual Studio extension/template for users of the framework. Keep it clean, minimal, and beginner-friendly; do not use it as a playground for testing random controls.

```powershell
dotnet run --project .\samples\ModernFormsNext.DemoApp\ModernFormsNext.DemoApp.csproj
```

Other broader manual-validation samples:

```powershell
dotnet run --project .\samples\Explorer\Explore.csproj
dotnet run --project .\samples\Outlaw\Outlaw.csproj
```

## Create a New Application

### Option 1: Use the Template

The repository contains a template package project in `ModernFormsNext.Templates`. After packing and installing that template package, create a new app with:

```powershell
dotnet new mfn-app -n MyApp
```

The generated project uses a code-first startup flow and references the current `ModernFormsNext` package version.

### Option 2: Create a Project Manually

Create a project file similar to:

```xml
<PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net10.0-windows</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
</PropertyGroup>
```

For source development inside this repository, use a project reference:

```xml
<ItemGroup>
    <ProjectReference Include="..\ModernFormsNext\ModernFormsNext.csproj" />
</ItemGroup>
```

For packaged usage, reference the package version produced by this repository:

```xml
<ItemGroup>
    <PackageReference Include="ModernFormsNext" Version="1.4.0" />
</ItemGroup>
```

### Create MainForm.cs

```csharp
using ModernFormsNext;

public class MainForm : Form
{
    public MainForm()
    {
        Text = "My App";
        Width = 800;
        Height = 600;
    }
}
```

### Create Program.cs

```csharp
using ModernFormsNext;

internal static class Program
{
    [STAThread]
    private static void Main()
    {
        Application.Run(new MainForm());
    }
}
```

## Notes

- The project is early-stage and APIs may change before a stable release.
- Windows is currently the best-supported backend.
- `ControlGallery` is the right place for visible control experiments and manual regressions.
- `ModernFormsNext.DemoApp` should remain aligned with the generated template experience.
